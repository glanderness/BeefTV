## 实际经过与结果

1. [seed.go](v2.0.5-client-recovery-acceptance/seed.go) 通过现有数据库迁移与 app 服务写入一条历史失败任务、成功创建回执和一个旧结构图片节点。任务 `v205-client-image`、画布 `v205-client-canvas`、节点 `n1`，初始 `failed / retrievable`、routeRun=3、revision=1。原回执的图片 URL 仅指向 `127.0.0.1:19118`。启动桌面前结束数据准备程序，不由夹具启动恢复线程。
2. [upstream.py](v2.0.5-client-recovery-acceptance/upstream.py) 作为常驻进程提供确定的 320×200 PNG。放行前阻塞图片响应，禁止 POST。正式客户端启动后，由自己的后台 worker 消费原回执，任务成为 succeeded、图片仍待下载。
3. 从客户端“项目”打开这张画布，关闭空助手面板、点击“适合屏幕”。完整画布显示“正在取回结果”、0 B；资源和结果均为 0，画布 revision=2。[下载前状态](v2.0.5-client-recovery-acceptance/before-download.json) 与 [原始截图](v2.0.5-client-recovery-acceptance/before-download.png) 已保存。
4. 北京时间 **02:08:22** 只放行假服务响应。之后没有刷新页面、点重试、切换画布或调用恢复/画布写入 API。完整画布自行显示四色白十字图片，[深色截图](v2.0.5-client-recovery-acceptance/after-dark.png) 与 AX 树均确认图片出现，取回进度消失。
5. 通过“画布外观”切换浅色，实际查看 [浅色截图](v2.0.5-client-recovery-acceptance/after-light.png)。本地 PNG 为 1263 字节，尺寸 320×200，SHA-256 `aafafc4d9e710ef860e6eb9c07e8de288026800a2a41112dc0813f3fb021a820`。保存了 [实际恢复文件](v2.0.5-client-recovery-acceptance/recovered-original.png) 和 [资源读回](v2.0.5-client-recovery-acceptance/resource.json)。
6. 关闭假上游，结束自有客户端进程，保留同一隔离数据和 WebKit 存储，再启动客户端并打开原画布。先保存了路由刚打开的 [首帧](v2.0.5-client-recovery-acceptance/restart-first-frame.png)，此时 AX 已有图片而截图尚未绘制，**不把首帧算作显示通过**；随后不作额外操作，实际看到 [重启后的图片](v2.0.5-client-recovery-acceptance/restart-offline.png)。回环端口连接返回 ECONNREFUSED，说明不依赖再次下载原 URL。

## 测试准备中遇到的问题

这些问题均发生在正式补验之前，不改产品代码，也不计入通过结果：

- 默认 Bun 缓存出现缺失条目，第一次安装报 ENOENT；改用本任务专用缓存后冻结锁文件安装成功，没有改依赖版本。
- 直接 `go build` 首次缺少 Wails CLI 默认添加的 `UniformTypeIdentifiers` 链接参数。对照本机已钉选 Wails `pkg/commands/build/base.go` 后补上该参数，构建成功；未更改 Wails 或项目源码。前后构建日志均保留，机器路径替换情况标在日志首行。
- 首次测试包缺少 `Resources/plugin-packages`，启动显示“工作区暂时无法打开”。保留 [截图](v2.0.5-client-recovery-acceptance/setup-failure.png)；运行仓库原打包脚本生成 86 个协议包后补入并重签，启动正常。
- 第一份夹具沿用组件测试里的硬编码 owner `local`，但真实迁移已经创建默认 workspace ID，因此页面未列出该画布。该测试实例退出；修正**夹具**为读取 `DefaultWorkspace().ID`，在另一个全新目录重新准备正式验收数据。`setup-*` 文件只属于这次废弃准备过程，不是正式通过证据。

## 重放与证据核对

证据内代码只用于本机免费夹具。桌面程序没有加载这些脚本，也没有任何产品修改。构建方式为冻结依赖、`bun run build:desktop`，将 `web/dist` 复制进 `backend/cmd/desktop/frontend/dist`，再使用以下命令（输出路径自行指定到隔离测试目录）：

```sh
cd backend
CGO_LDFLAGS='-framework UniformTypeIdentifiers' go build -trimpath -tags production \
  -ldflags '-X infinite-canvas/backend/internal/buildinfo.Version=v2.0.5 -X infinite-canvas/backend/internal/buildinfo.Commit=6a155448' \
  -o <隔离测试包>/Contents/MacOS/BeefTV ./cmd/desktop
```

测试包的 Info.plist 从原应用读取，仅更改测试 bundle id、名称和版本，并移除 URL scheme 注册；加上本源码生成的官方协议包后 ad hoc 重签。签名只用于启动隔离测试，不是 Apple 公证或正式发布签名证明。

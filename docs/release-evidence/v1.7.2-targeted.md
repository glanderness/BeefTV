# v1.7.2 assistant local channel regression evidence

## Candidate and scope

Issue [#68](https://github.com/glanderness/BeefTV/issues/68) reports that the canvas assistant cannot resolve a custom local channel despite an enabled channel, stored key, OpenAI format, a models list and a default text selection. The resolver required a matching model profile, while this persisted configuration had none.

Product candidate `b31d35f72c1e0c94a7fe82f9ea309cccee59906b`, based on `36c9f67`, fixes backend resolution and the frontend model picker. Its source digest is `7e3b1251aa76a6f38b1aade1d4409d16ab2b02ace7502c9f2031e5cf6a470d22`. A profile-free custom model is accepted only when it is the selected default text model and its channel protocol is supported. Explicit capabilities, disabled channels, managed-channel restrictions and credential checks remain in force.

## Verification performed

- Before the patch, a saved models-only OpenAI channel reproduced `model_not_configured` for both the bare model name and the channel-qualified name. Both pass with the patch; the service test uses no database channel rows.
- The HTTP lifecycle regression reads the same persisted configuration through `/api/assistant/host/config`, checks the model/channel/protocol/hasKey projection and rejects secret disclosure.
- Channel tests cover default OpenAI and Claude protocols, explicit Responses, unsupported formats/protocols, disabled channels, missing keys, unlisted models, system/managed channels, explicit unclassified selections, conflicting model profiles and a default on another channel.
- Full `go test ./...` passed after building official protocol packages. An earlier run without those required packages failed on missing adapters; it is not counted as passing evidence.
- Frontend focused tests: 16 passed, 65 assertions, zero failures. Browser coverage includes the custom models-only default surviving reload, both themes at 390px, curated managed options and the existing save-before-dispatch barrier. TypeScript checking passed.
- `scripts/verify-beeftv-local-release.sh` passed, including production web build, route/storage checks and release size checks.
- The actual Node host startup test passed using Node 24.15.0 and isolated test data, reading a models-only local snapshot and reporting the selected channel as available. No model calls were made. The fixture's missing `durable-request-budget.mjs` was corrected to match the shipped runtime modules.
- [Quality checks](https://github.com/glanderness/BeefTV/actions/runs/37087977795) passed Backend, Web and Release publisher jobs. [Director P0 Chrome E2E](https://github.com/glanderness/BeefTV/actions/runs/37087977741) passed. The optional platform matrix was not executed by these PR-triggered runs.

# Part 01 · BeefTV 字体与排版规范 v1

本文属于 [BeefTV UI 系统](README.md)的字体分册；界面组织与覆盖治理见 [Part 02](interface-and-style-governance.md)。

日期：2026-10-29。适用范围：桌面工作区及其弹窗、侧栏、菜单、表单；基准页面为首页 `/`、项目库 `/project`（`/projects` 同入口）、资产库 `/assets`。

本规范是后续 UI 调整的目标标准，不代表所有现有界面已经符合。正文中的“标准”是本次归纳后确定的规则；“现有例外”保留基准页面精调结果；[审计文档](typography-audit.md)记录静态源码证据与尚未迁移的问题。后台、画布缩放坐标中的节点、视频字幕、导出作品和营销页面不直接套用此表。

## 1. 核心原则

- 先删除无助于理解或操作的文字，再安排层级。不要通过缩小、降低透明度来隐藏冗余说明。
- 页面标题克制，正文可读，辅助信息从属。字号只表达层级，不代替布局和信息组织。
- 一个普通内容区域通常只需要标题、正文、辅助信息三层；无需叠加大标题、副标题、来源、编号和重复提示。
- 相同角色跨页同值；选中、悬停和加载不改变字号、行高、字距，不造成文字或按钮跳动。
- 数值均为 **CSS px**，不是截图物理像素。以缩放 100% 为检查基点；DPR 2 的截图不意味着字号翻倍。

## 2. 字体家族

### 工作区普通文字

以当前工作区启动入口声明的系统字体栈为基线：

```css
font-family: "SF Pro Display", "SF Pro Text", "PingFang SC",
             "Microsoft YaHei", "Helvetica Neue", sans-serif;
```

这是字体匹配顺序，不是跨系统都安装了这些字体的承诺。macOS、Windows、Linux 允许系统回退的字形差异，但同一系统中的页面、控件和浮层须使用一致的声明栈。中文使用系统中文回退；不额外引入装饰字体，不对中文强制使用英文字体。

现有 `--font-sans` 则声明 Inter 优先，且 AntD 部分主题使用该变量；它与启动入口并不一致。**本次不直接改动任何字体变量。** 后续迁移应先将工作区、其浮层和控件字体集中为同一入口，并在三个基准页面验收；禁止仅新增一个 `font-sans` 类就宣称统一。Inter 与系统字体的宽度差异必须纳入回归。

### 代码和技术正文

仅代码、Markdown 源码、命令、内容摘要等需要等宽排版的内容使用 `--font-mono`：

```css
font-family: "JetBrains Mono Variable", "JetBrains Mono",
             ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

技能名称、普通简介、日期和版本标签不使用等宽字体；需要数字对齐时使用数字特性而不是替换整个字体。

### 品牌

BeefTV 标志属于品牌资产，不套普通标题规则。优先复用现有 Logo；现有文字回退的 20px、780 字重、斜体及 `-.055em` 字距仅限品牌，不扩散到导航和标题。

## 3. 标准角色表

除显式例外外，字距统一为 `0`，字体样式为 `normal`。表内行高是文字行盒高度，不是按钮高度或区块间距。一个角色必须作为完整组合使用。

| 角色 | 字号 | 行高 | 字重 | 文字色 | 使用位置 |
| --- | ---: | ---: | ---: | --- | --- |
| `page-title` | 16px | 22px | 500 | 主文字 | 页面标题、侧栏标题、普通弹窗标题 |
| `section-title` | 16px | 24px | 500 | 主文字 | 页面内部主分区、首页“最近项目” |
| `item-title` | 14px | 22px | 500 | 主文字 | 普通列表条目、内容名称、次级分区 |
| `body` | 14px | 22px | 400 | 主文字或次级文字 | 可读正文、技能简介、一般说明 |
| `body-long` | 14px | 24px | 400 | 主文字 | 多段说明、长文预览；不用于普通按钮 |
| `navigation` | 14px | 22px | 400 | 常态次级，选中主文字 | 全局侧栏、同级导航、标签页 |
| `control` | 13px | 20px | 400 | 主文字 | 输入内容、选择项、菜单项、分页文字 |
| `button` | 13px | 20px | 550 | 对应按钮前景色 | 标准按钮，与现有工作区 Button 字重一致 |
| `button-small` | 12px | 18px | 550 | 对应按钮前景色 | 紧凑列表中的次级按钮 |
| `field-label` | 12px | 18px | 500 | 次级文字 | 表单字段名称；不附加冗余“可选”字样 |
| `caption` | 12px | 18px | 400 | 次级文字 | 日期、版本、必要的辅助说明、状态描述 |
| `placeholder` | 与输入内容相同 | 与输入内容相同 | 400 | 辅助文字 | 输入示例；不替代字段标签 |
| `empty-title` | 14px | 22px | 500 | 主文字 | 空状态标题 |
| `empty-description` | 12px | 18px | 400 | 次级文字 | 一句有行动方向的空状态说明 |
| `code` | 12px | 20px | 400 | 主文字 | 等宽源码、命令和结构化技术内容 |

这些角色是文档中的语义名，**不是已经注册的 CSS 类或变量**。有完整匹配的共用组件时优先复用；没有时按第 9 节集中落地，而不是为页面另建同义字号。

### 字重规则

常规内容以 400、500 为主。550 限于既有按钮，580/600 限于下面记录的卡片例外。不要从现有全局文件中的 620、650、680 等任取数值用于新标题。字重不足时优先检查字体是否成功匹配，不用描边、阴影或重复渲染模拟加粗。字重是 CSS 请求值，实际字体是否有对应档位由平台字体决定。

## 4. 基准页面现有例外

保留这些已精调组合；不把它们推广成所有页面的新默认。

| 场景 | 已有组合 | 处理规则 |
| --- | --- | --- |
| 首页新建入口 | 16px / 24px / 500 / 字距 0 | 仅展示入口，不作为普通按钮档位 |
| 首页创作能力名称 | 14px / 22px / 400 | 不因使用 `<strong>` 就自动设成粗体 |
| 首页最近项目名称 | 14px / 22px / 500 | 使用首页卡片组合 |
| 首页“查看全部” | 13px / 20px / 400 / 次级文字 | 文本动作，不与分区标题等重 |
| 首页日期 | 12px / 18px / 400 / 次级文字 | 使用 `caption` |
| 首页分区标题 | 16px / 24px / 500 / `-.01em` | 保留现有轻微负字距；新区域默认 0 |
| 项目库卡片标题 | 13px / 20px / 600 | 密集预览卡片例外；文件夹与项目共用壳 |
| 项目库卡片日期 | 11px / 18px / 400 / 辅助文字 | 仅既有项目卡片，不作为新正文档位 |
| 资产卡片名称 | 14px / 22.4px（1.6）/ 580 / `-.01em` | 保留现有 CSS 组合；不要误写成项目卡片的 13px |
| 首页窄屏新建入口 | ≤900px 时字号 22px，继承 24px 行高 | 已有响应式例外，非普通页面标题标准 |
| 顶栏工具入口 | 14px / 20px | 保留已有组件值，不反推为所有按钮标准 |

资产卡片日期另有 9px 和低透明度的历史覆盖，见审计文档：它是当前实现的可读性欠账，不是应推广的标准。本轮不改变基准页面；后续单独验收。新页面的日期默认用 12px，而不是复制此覆盖。

## 5. 颜色与深浅

普通工作区文字使用主题语义色，不在各页自行写 `#999`、`text-white/45` 或局部透明度。

| 层级 | 变量 | 浅色当前值 | 深色当前值 | 职责 |
| --- | --- | --- | --- | --- |
| 主文字 | `--user-ink` | `#1d1d21` | `#f3f3f5` | 标题、字段值、主要内容、选中导航 |
| 次级文字 | `--user-ink-muted` | `#686872` | `#b4b4bc` | 简介、必要说明、状态、常态导航 |
| 辅助文字 | `--user-ink-soft` | `#85858e` | `#9797a1` | 占位符、非关键元数据；不能承载唯一的操作指引 |
| 实心按钮文字 | `--user-action-foreground` | 主题映射 | 主题映射 | 必须与对应动作背景成对使用 |

颜色值用于对照审计，业务组件应引用变量。浮层通过 `.app-user-overlays` 获得工作区色阶；不要以浮层位于 `body` 外为由换另一套灰度。`--foreground` / `--muted-foreground` 属于另一套主题变量，未经比对不要当作上述变量的同义词。

状态规则：

- 导航选中或悬停从次级文字切到主文字，用底色、标记共同表达；保持 14px/22px/400，禁止加粗导致宽度变化。
- 普通文本链接常态次级、悬停主文字；长正文中的链接另有下划线等可识别线索。焦点环不依靠文字变色代替。
- 错误、警告、成功引用现有语义状态色，并附可读文字或图标，不能只靠红绿区分。
- 禁用使用组件状态，不能对整个文字容器叠加透明度而连带压暗重要说明；不可用原因仍需可读。
- 重要操作说明、费用、错误和确认文字不能使用辅助灰来追求“简洁”。

### 可读性门槛

本项目对新增界面采用普通文字与其实际背景对比度至少 4.5:1 的验收目标。须计算最终合成颜色，不能只看变量名或透明度数值。

当前浅色 `--user-ink-soft` 对 `#f8f8fa` 约 3.45:1，对白色约 3.66:1，**不满足这个普通文字目标**。因此需要被读懂的日期和说明应选次级文字色；新页面必要时显式用次级色作为占位符，不能以继承到辅助色为理由忽略检查。旧基准页面暂保留，后续分项验收。深色与浅色必须分别检查，不假设同名变量在两种主题下都达标。

## 6. 行高、字距与段落

- 普通中文、英文及混排字距 0。禁止给中文导航、按钮和表单标签套 `tracking-wide`、大写标签风格或随意负字距。
- 内容过宽先修容器和文案，不通过压缩字体、负字距、`scale()` 或缩小字号塞入。
- 13px 配 20px；14px 普通配 22px、长文配 24px；12px 配 18px。不得在每页另取近似值。
- 输入框与按钮使用自身布局居中，不能把 `line-height` 设置成整个控件高度。多行按钮要重新考虑文案或布局。
- 段落间距与行高分开处理：普通简介与标题间距可从基准组件继承；长文段间建议 12px，字段标签到控件建议 8px。这两个是排版节奏建议，不是已完成的全局间距规范。
- 一行文字不额外留空段；删除副标题时同步检查它的 margin 和占位。
- 同层标题不同时使用不同字号和不同字重制造多个重心。短说明建议控制在约 58–64ch 宽度，中文须结合实际字形复核，不把 `ch` 当作中文字数。

### 字形、语义与渲染细节

- 普通 UI 不使用斜体、全大写转换、文字描边或文字阴影。品牌及用户原始内容除外。
- 不在页面级修改字体平滑设置、`font-synthesis` 或渲染缩放来补偿观感；如需统一，须在共享入口评审，并检查不同平台的字重变化。不能以截图中的抗锯齿差异反推字号。
- 标题使用正确的标题语义，标签与控件建立可访问关联；字号由角色决定，不依赖浏览器对 `h1`/`strong`/`small` 的默认样式。
- 图标与文字居中由控件 flex/grid 对齐处理，不用负行高、逐项 `translateY` 或插入空格凑基线。
- 输入光标、选中文字及焦点状态沿用共享主题，保证前景与选区背景可读；不要在页面里禁用文字选择来掩盖排版问题。
- 新增普通 UI 不采用 7/9/10px 档位；辅助说明默认 12px。11px 仅限记录过的紧凑元数据例外，不能缩小错误、按钮或输入内容。

## 7. 截断、换行和数字

- 卡片名称允许单行省略；必须保留可访问名称，并能通过详情、Tooltip 或 `title` 查看完整名称。不能让名称成为纯装饰图片。
- 列表简介可按场景使用两行截断，完整内容在详情可读。报错、费用、授权和确认内容不截断。
- 文件名、URL、摘要等长串在需要换行的位置使用 `overflow-wrap: anywhere`；代码块按其阅读任务选择横向滚动或换行，不把全站都设为 `word-break: break-all`。
- 需要对齐的计数、时间、表格和进度使用 `font-variant-numeric: tabular-nums`；普通句子不用强制等宽数字。
- 版本号用普通字体；代码里的标识符才用等宽字体。名称和版本分层，不把版本并入用户可编辑的名称。
- 中文标点使用中文全角形式，代码、URL 和版本保持原始内容，不为视觉一致改变技术数据。

## 8. 响应式和平台

- 普通界面在窄窗口优先重排、换行或折叠操作，不整体缩小字体；不照搬首页展示入口的 22px 响应式例外。
- 在同一主题与缩放下比较页面；至少检查桌面宽度与窄窗口、浅色与深色、中文长名称与中英数字混排。
- 尊重系统/浏览器缩放，不禁用文字缩放，不使用整页 `transform: scale()` 达成“紧凑”。
- 不为模拟另一平台截图而强行安装或携带商业系统字体。字体不可用时验证回退后的省略、控件高度和混排基线。

## 9. 开发落地约束

1. 优先使用共享 `PageHeader`、工作区导航及现有卡片壳，不复制它们再加局部覆盖。
2. 当前 `--fs-body=14px`、`--fs-caption=12px`、`--fs-heading=16px` 仅提供字号，不包含字重、颜色、行高。不得以“用了 token”代替完整角色检查。
3. **`--fs-label=11px` 不等于本规范的表单标签**。表单标签标准为 12px；不要按变量英文名猜用途。
4. 13px 控件档及标准行高等尚未全部集中注册。后续实现应在共享 token/排版工具层一次定义，再迁移调用点；文档中的角色名在实现前不能直接当类名使用。
5. `.typ-title-sm`、`.typ-nav-link` 等现有工具类的组合与本规范不完全相同。调用前核对，不能直接批量替换。
6. 不新增页面私有的字号阶梯、任意 opacity 或 `!important` 链来绕过角色。必要的修复应落到明确组件边界。
7. 样式表越靠后不一定生效更高：同时检查 cascade layer、选择器优先级、行内样式、`!important`、主题与响应式。禁止仅凭文件中的第一次声明确定最终值。

示例（数值说明，**不是本次新增的运行时实现**）：

```css
/* 共享层未来注册的角色组合；业务页复用角色，不复制此片段。 */
.ui-page-title {
  font-family: inherit;
  font-size: var(--fs-heading); /* 16px */
  font-weight: 500;
  line-height: 22px;
  letter-spacing: 0;
  color: var(--user-ink);
}
```

## 10. 评审清单

- [ ] 每种文字有明确角色，字号、行高、字重、字距和颜色能对应本表或记录的例外。
- [ ] 页面标题没有套 22px 的历史 `--fs-title`；导航选中没有额外加粗。
- [ ] 表单、原生控件、AntD、侧栏和 Portal 浮层没有混用字体家族。
- [ ] 辅助灰没有承载必须读懂的操作说明；两种主题检查实际背景与合成对比度。
- [ ] 中英混排、长标题、数字、省略和窄窗口可读；完整内容有查看入口。
- [ ] 删除冗余文案后没有留下行盒、margin 或空区占位。
- [ ] 三个基准页无未经授权的视觉变更；新增例外已写入审计记录。

## 11. 后续迁移顺序

先统一字体入口和完整排版角色，再按页面迁移，最后移除旧覆盖。保留每一步的安装版验收记录。资产 9px 日期和浅色低对比辅助文字应单列修复，不以“已有基准”解释为可无限复制。布局、间距、圆角等系统规范另行制定，不在这一阶段顺带改变。

# BeefTV UI 系统

以经过人工精调的**首页、项目库、资产库**为视觉基准，逐步建立覆盖画布外页面及其浮层的设计与实现约束。字体与排版是系统的一部分，不是整个系统。

## 系统分册

| Part | 主题 | 当前状态 |
| --- | --- | --- |
| 01 | [字体与排版](typography.md) | 标准已文档化，运行时尚未全面迁移 |
| 02 | [画布外界面结构与样式治理](interface-and-style-governance.md) | 结构、样式所有权、反馈及迁移规则已文档化，待分批实现 |
| 03 | 颜色、层级与基础 token | 待整理；现有文字色先由 Part 01 约束 |
| 04 | 布局、间距、尺寸、圆角和图标 | 待整理；本轮仅确立职责和已有基准，不视为完整数值表 |
| 05 | 组件与交互模式 | 待整理；本轮先明确列表、表单、浮层、状态的组织原则 |
| 06 | 动效、性能与无障碍细则 | 待整理；本轮先明确单一反馈所有者、稳定布局与可读性底线 |

待整理分册是维护计划，没有独立规范文件，也不意味着这些数值或组件已经实现。后续按用户确认的范围补充，可调整分册边界；避免不同 Part 重复定义同一语义。

## 使用与维护

1. 按文字用途选 Part 01 的完整排版角色；按界面职责选 Part 02 的壳、内容与状态模式。
2. 一个属性族有明确的主要所有者。相同组件跨页一致，禁止靠新增 final-lock 或重要级别竞赛实现一致性。
3. 规范说明目标，审计说明现状，候选清单提供线索；三者不能互相冒充。不要将静态审计写成实机验收，也不要将文档化写成已全站实施。
4. 新页面遵循规范，旧页面逐组件迁移。未经人工验收，不批量改变首页/项目/资产的精调外观。
5. 新增例外必须记录职责、来源、数值、原因、验收状态和移除条件；已有例外不自动扩展到新页面。
6. 每批先更新共享所有者，再迁移调用点，移除旧规则并补验收记录；不清理或覆盖用户其他未提交修改。
7. 工作区内的画布编辑器不在本轮范围。修改混合全局样式时记录共享边界，不能以“画布外审计”为名全局删除画布规则。

文档建立与扩展日期：2026-10-29。当前为源码审计和规范建设阶段；本轮没有改变页面样式、重建 App、提交或推送。

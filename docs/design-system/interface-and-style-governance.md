# Part 02 · 画布外界面结构与样式治理

日期：2026-10-29。适用范围与证据见[画布外审计](outer-ui-audit.md)。本规范约束后续开发和渐进迁移，不代表现有组件已全部符合。字体、字重、行高、字距及文字色遵循 [Part 01](typography.md)，不在这里再定义一套。

## 1. 统一的界面逻辑

让用户在任意页面都能回答：我在哪里、正在看什么、主要能做什么、操作是否完成。

```text
页面标题 + 页面级动作
同级导航（确有多个内容集合时）
工具栏（搜索 / 筛选 / 排序 / 刷新）
内容区（列表、卡片或表单中的一种主要结构）
底部翻页或固定提交区（按任务选择，不在每页重复堆叠）
```

不在上述层级间插入重复副标题、装饰性说明、版本、技术标识和多个同权重按钮。工作区页头已有当前页面名，内容区不再重复一个同名大标题。帮助信息按需出现于空态、具体字段、详情或首次使用指引。

### 页面职责

| 类型 | 主要任务 | 常驻内容 | 按需内容 |
| --- | --- | --- | --- |
| 首页 | 开始或继续创作 | 创作入口、近期项目 | 首次指引、必要错误 |
| 资源集合（项目/资产/技能） | 找到并打开对象 | 导航、工具栏、对象、主要动作 | 版本、来源、许可、次要管理操作 |
| 我的资源 | 管理持有对象 | 与发现页同一种对象表达、真实状态 | 编辑、历史、分享、删除菜单 |
| 投稿/任务记录 | 了解进度并继续 | 名称、简述、当前状态、详情 | 账号管理、完整文件、阶段确认 |
| 设置 | 修改明确配置 | 分组、字段、当前值、必要校验 | 高级项、协议细节、帮助 |

相同对象在发现、安装、持有、详情中的名称和主要介绍保持可识别。状态必须由真实 ID/版本/关系判定，不能因名称相同就宣称已安装，也不能把不同版本简单当作可更新。自建副本与市场原件保持明确身份。

## 2. 一个属性族，一个主要所有者

| 职责 | 所有者 | 页面可以做什么 |
| --- | --- | --- |
| 字体、颜色、间距、状态、动作时长原始值 | 共享 Primitive / Semantic token 层 | 选择语义，不复制另一组原始值 |
| 外部工作区导航、顶栏、页面容器 | 工作区壳 | 传路由/选中状态，不能反向覆盖壳的宽度和底色 |
| 页头、工具栏、列表/卡片、分页 | 共享产品组件 | 传内容和明确变体，不复制整块 CSS |
| 业务专属网格、媒体内容、字段条件 | 页面/业务组件根命名空间 | 只负责自身内容，不重置全站 AntD 或父壳 |
| 弹窗/侧栏尺寸、标题栏、滚动、底部动作 | AppModal / AppDrawer 及共享内容壳 | 选模式/size/slot；不从任意 CSS 强锁 wrapper 宽度 |
| hover/focus/disabled/loading/selected | 对应基础组件或模式件 | 传状态，不额外叠加全局反馈 |
| 第三方 DOM 适配 | 集中且有范围的适配层 | 记录第三方版本和原因，不散落各页 |

“主要所有者”不禁止响应式、主题和状态分支；要求这些分支聚在同一个边界内，而不是让不同文件互相撤销。

推荐职责组织（未来迁移目标，目录和文件尚未全部建立）：

```text
tokens（原始值 → 语义值 → 组件参数）
  → base components / third-party adapters
  → workspace shell + product patterns
  → page-scoped composition
```

按职责划分，不按“旧版 / 新版 / final / final-lock”划分。现有 globals 不一次搬空；先迁移一处职责，再删除该处旧声明。若未来引入 CSS layers，必须先验证 Tailwind、AntD、普通声明和 important 的级联次序，不能仅改文件排列就上全站 layer。

## 3. 样式覆盖纪律

1. 不新增 `*-final`、`*-lock` 或“追加到文件尾部兜底”的样式层。
2. 同一选择器/属性/条件出现第二个所有者时，先确认是否应修改原所有者；确需兼容覆盖必须写明原因和移除条件。
3. 新增 important 只用于有明确边界的第三方适配、必要的用户偏好等情况，评审中记录原因；禁止页面用 important 去打赢另一页面。
4. 状态使用 `data-state`、`aria-selected`、`aria-pressed` 或明确变体类。不要依靠中文 `aria-label` 文案字符串定位几何，不用 `> div:first-child` 绑定实现细节。
5. 页面 CSS 限定页面根；共享普通选择器在共享层定义。不能因为是“页面懒加载 CSS”就假设卸载路由后规则消失。
6. 删规则前核对同一条件、值、重要级别、简写/长写、继承、状态、Portal 和第三方 DOM。机器候选不能直接自动删除。
7. 合并规则时保留已确认外观和响应式例外。一次迁移只改变一个职责，避免“顺手修一切”。
8. 文档中的建议类名/目录不等于已经可调用的实现；新增公用角色须先在共享层注册。

## 4. 页头、工具栏和内容节奏

- 页面标题、标签页、工具栏、内容左边缘建立稳定对齐；右侧操作建立稳定的操作列。
- 保留基准 PageHeader 的 64px 页头节奏和共享容器已有桌面40px、≤720px的20px内边距作为起点。资产页已有16px窄屏覆盖暂作例外，先验收再统一，不从本规范反推应立刻覆盖它。
- 搜索、筛选和排序只在一条工具栏编排；窄窗口自然换行，不能缩小文字或强塞控件。
- 资源列表以名称、简述、右侧动作组成；管理页沿用同一对象结构，状态和操作随任务变化。
- 次要操作收进菜单；删除、断开等不持续与主要动作争夺视觉注意力。菜单项仍按真实权限和能力提供。
- 卡片和列表的区别取决于是否需要媒体预览，不为每个文本对象都增加厚重卡片。保留首页/项目/资产的现有卡片例外。
- 空态以一个短标题、一句指引和至多一个主要入口表达；已有工具栏主入口时避免在附近重复同一个按钮。错误态不伪装成空态。

间距、圆角和图标的完整数值表尚未定稿；这里确定组织规则，不另建临时 token 阶梯。

## 5. 详情、创建与导入的一致性

- 对象详情承载版本、许可、文件和完整说明；创建/编辑聚焦必须输入的内容；导入聚焦文件/来源及导入结果。
- 侧栏适合保持列表上下文的编辑；弹窗适合独立确认与详情。优先复用现有模式，不根据单个截图任意改壳。
- 壳统一标题位置、关闭入口、滚动区和底部主操作。页面不再同时提供两套关闭/取消入口或两套标题。
- 高级项折叠后仍保留原值；错误发生时展开对应区域并定位字段，不能让用户面对不可见的校验失败。
- 删除解释性小字时判断是否承载费用、授权、错误或未保存状态。冗余文案可删除，操作决策所需的信息必须在合适位置保留。
- 保存/生成期间防止重复提交；异步结果不得回写已切换的对象或已关闭表单。未保存内容的关闭行为统一、可预期。
- 投稿的上传与送审是两个独立确认，不因视觉精简而合并或自动执行。

## 6. 滚动与响应式

- 每个页面/浮层声明一个主要纵向滚动所有者；固定页头与底部动作由父 flex/grid 分配，内容区域设置 `min-height:0`。
- 列表分页固定在页面内容区底部，左右居中；长列表滚动不推走分页。普通列表采用统一样式，特殊历史流可保留经记录的加载更多模式。
- 折叠导航、移动导航、详情浮层都不能在关闭后继续占据主布局宽度。
- 代码、媒体预览可有独立滚动；不把外层页面、详情 article、Form 再各加一个竞争的纵向滚动条。
- 使用容器布局和已确定的组件断点处理窄窗口；不因截图宽度固定所有内容，也不在本轮强行合并不同用途的720/900/1023断点。
- 基准页已有窄屏例外必须记录；新组件优先使用清晰的布局模式，而不是逐项 `top:-Npx` 修补。

## 7. 流畅感与反馈

流畅首先是布局稳定、状态连贯、反馈可见，而不是动画数量。

- 第一次读取可用占位；搜索/刷新期间尽量保持工具栏、列表宽度、滚动位置和分页结构，避免整页反复卸载。分页/搜索改变时有明确 loading 状态，错误不清空已有有效结果。
- 页签切换、弹窗开关、菜单展开不改变字体和控件几何，不通过反复挂载组件重放动画。
- 一次点击只由一个层负责按压反馈。全局 hook、CSS 和组件动画不能分别再演一次同样动作。
- 状态过渡优先 opacity/transform，不使用 `transition: all`；这不等于已测得 GPU 加速或性能提升。对 blur、backdrop-filter、大片位移是否造成卡顿，必须采样验证。
- 尊重 prefers-reduced-motion，保留键盘焦点；关闭动画不得破坏浮层定位或完成事件。
- 失败必须在当前任务上下文中可见，必要时支持重试。不能全局隐藏 message 后继续将它当作唯一报错渠道。
- 成功只有在保存/安装等真实完成后出现；点击动效、loading 消失和弹窗关闭都不等于成功。
- 使用现有 `--user-motion` 和产品组件已有动效参数作为迁移输入，完整动效档位在后续 Part 定稿，不在本轮新增一套时长变量。

## 8. 验收与防止复发

每个组件批次至少核对：

1. 三个基准页与相关页面；桌面/窄窗口、深色/浅色、长名称和中英混排。
2. 冷启动直达、首页→资产→项目→技能→设置→首页，以及反向顺序；检查返回后的大小、颜色、滚动和浮层。
3. 常态、选中、悬停、键盘焦点、禁用、加载、空态、错误和成功；不能只验收第一屏。
4. 浮层关闭/返回时焦点、未保存行为、固定底部动作、Select/菜单定位。
5. 共享规则是否服务画布；涉及共享边界时只隔离外部职责，画布迁移另做。
6. 静态清单中对应候选已更新，旧所有者已移除，没有新的 final-lock/important 链。
7. 有性能目标时记录同环境前后采样；无采样不宣称帧率或性能提升。

验收记录至少包含：改动职责、旧/新所有者、App版本、窗口与缩放、主题、访问路径、实际结果、未覆盖项。用户完成本地 App 验收后按工作区规则分别提交和 push。

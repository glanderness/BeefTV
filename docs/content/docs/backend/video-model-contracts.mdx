# 视频模型与参考素材合同

视频任务统一经过素材归属检查、能力检查、素材读取、协议适配、任务轮询和结果保存。模型名称相似不代表请求格式或素材能力相同。

## 企业模型

`backend/internal/providerpreset/video_contracts.json` 是已核验企业视频线路的共用声明，后端模型目录、素材处理和前端配置直接读取同一份文件。声明包含匹配模型、协议、是否允许内嵌素材，以及有明确限制时的参考素材数量和生成模式。

`maxReferences` 可只约束部分素材类型；未声明的类型保留原有模型能力限制，`0` 明确表示不支持该类型。前后端都遵循这一规则。

- Seedance 2.0 / 2.5 使用既有 Seedance 请求处理和素材规格检查。内置 BeefAPI 线路的本地参考图片、视频、音频由本机后端先交给同一企业接口签发的短期地址，再在 `/v1/videos` 只发送 HTTPS 链接，避免把整份文件编进 JSON。工作区已有公开访问地址时，仍上传这些本机文件，不改成工作区自己的地址。调用方已经提供的 HTTPS 或 `asset://` 地址保持原样。不自动裁剪、压缩或截断。旧接口没有该上传能力时，仅在整次 JSON 仍不超过 64MiB 时沿用内嵌数据。直连方舟、自定义渠道和其他模型保持原传输方式。
- Wan 3.0 当前线路支持文生视频和单图生视频，本地图片按内嵌数据提交。当前 BeefAPI 适配器只能传递一张图片，参考视频、参考音频和多图会在提交前拒绝；这是当前接入能力，不代表模型本身永远不支持这些输入。
- 未声明的模型保留模型目录或用户明确选择的协议，不根据供应商品牌放开本地素材支持。
- 通用素材处理遵循已安装插件的 `requiresPublicMediaUrls` 声明。要求公网地址的线路不会把本机地址发送给上游，也不会自动公开用户文件。
- 只接受公网链接的渠道会在任务入队前检查参考素材，并指出需要替换的图片、视频或音频序号。可换用 HTTPS 素材链接，或在渠道设置中选择与服务商实际接口相符、支持本地素材的协议；不会仅凭模型名称自动切换协议。

## 自定义全参视频服务

服务商支持分片素材上传及全参视频接口时，在模型的高级设置中选择「全参视频」协议。模型名称本身不能证明协议兼容；请按服务商的接口说明选择。

图片、视频和音频参考先上传到所配置的 API 服务，完成后核对字节数与 SHA256，再提交视频任务。素材地址默认必须与 API 同域。如果服务商另有素材域名，在连接的「高级设置」中填写「素材服务地址」，只填 HTTPS 域名，不带路径或查询参数。此设置仅允许该域名返回素材地址，不会向它发送 API Key。

任务结果若返回以 `/` 开头的相对地址，客户端按所配置的 API 源站解析。下载仍受外部地址校验约束；只有同源下载使用该服务的凭据。

## 新增模型验收

1. 核验当前线路的创建、查询和结果格式，以及每种参考素材的传输方式、数量、大小、时长和格式限制。
2. 复用已有协议插件；确有不同线协议时再增加插件。企业线路的例外能力写入共用合同，不在页面中增加模型名称判断。
3. 添加合同与请求测试，覆盖本地素材、数量边界、未知模型不继承能力、配置重载，以及插件缺失或停用。
4. 实际提交最小样例，验证任务终态、结果可读取和保存；接单成功不能替代生成成功。

新增模型仍需要协议核验与实际验收；共用流程减少重复实现，不代替供应商能力确认。

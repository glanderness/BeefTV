## Seedance 2.5 的任务模式

依据[火山官方 2.5 指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)，模式会决定哪些输出参数可以自定义：

| 模式 | 素材角色 | 比例 | 时长 |
| --- | --- | --- | --- |
| 文本或语义参考生成 | `reference_image/video/audio` | 可设置 | 可设置 |
| 首帧、首尾帧 | `first_frame/last_frame` | `adaptive`，跟随首帧 | 可设置 |
| 编辑视频 | 参考视频及其他参考素材 | `adaptive` | `-1`，跟随原视频 |
| 延长视频 | 参考视频及其他参考素材 | `adaptive` | 可设置 |

2.0 与 2.5 的模式约束不同，不应把 2.5 的规则全部套到 2.0。模型别名（包括 `seedance-2.5-official`）也需要命中对应版本。

BeefTV 保留明确的素材角色和已选模式。2.5 首帧任务显式发送自适应比例；不依赖省略参数后的供应商默认值，也不将自适应改成横屏比例。明确的编辑、延长请求使用上表参数；普通参考视频不会仅因含有视频就自动改成编辑或延长。界面只显示当前渠道已声明支持的模式。

模型可能依据提示词判断编辑、延长意图。客户端不通过关键词猜测并改写用户请求；若模型判定的任务类型与所选参数不兼容，会提示调整比例、时长或任务模式。画布专业模式可明确选择参考生成或首尾帧，具体能力以当前渠道为准。

## 三层限制分别核对

### WhatsToken 线路的画幅兼容

BeefAPI 渠道层对 WhatsToken 的 `seedance-2.5-official` 首帧请求读取图片尺寸，将 `adaptive` 转成同一固定比例。仅接受能够精确对应 1:1、4:3、3:4、9:16、16:9、21:9 的图片；不裁剪、不按最近比例取整。其他渠道及火山直连保留原生合同。无法读取尺寸或无法保持比例时，客户端提示重新上传、调整首帧或更换模型。

BeefTV 的 2.5 首帧设置显示“随首帧”，编辑/延长显示“随原视频”；编辑时长也随原视频。切回参考生成后恢复自由设置，保留用户原先选择。

已知 WhatsToken 2.0 标准版和 2.5 带参考视频时可能忽略固定比例。内置企业渠道及直接配置的 WhatsToken 渠道对此在画布实际提交前提示风险，由用户选择返回调整或继续付费生成；Fast、Mini、普通文生和火山直连不触发该提示。该提示是临时的已知线路提示，不代表网关的动态路由能力接口；线路修复或切换后应复验并更新提示范围。

任务结果按提交时的参数与读到的实际视频尺寸比较，明显不符时保留原片并在结果卡提示；忽略小幅编码尺寸偏差。没有媒体尺寸时不猜测结果。提示不会自动发起新任务、裁剪、修改账单或承诺退款。

内置 BeefAPI 的 Seedance 2.0/2.5 通过 Videos API 提交全能参考。配置加载会修复旧版本自动写入的“视频、音频参考数量为 0”配置，并保留无关自定义限制。模型目录导入、重新连接和重启后均应保留参考能力；不要仅验证手工构造的能力对象。用户自定义渠道的明确限制仍按其配置执行。

本地素材最终是否可发送还取决于接入渠道的媒体合同。WhatsToken 官方线路需要 HTTPS 素材地址，由 BeefAPI 在网关侧完成受控暂存；界面允许选中模型不等于上游已完成素材校验。

1. **模型能力**：模型版本、任务模式、素材种类、数量、单段和总时长、尺寸、分辨率。
2. **接入合同**：方舟原生 API、BeefAPI `/v1/videos`、第三方中转的字段与默认值分别核对，不能互相代替。
3. **内容审核**：输入、输出及图片、音频、视频的审核结果不等同参数错误。修改尺寸无法解决版权审核失败。

素材数值限制参考[官方 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)和具体渠道的能力配置，不把提示词指南中的效果建议当成硬限制。

## 异步报错与排查

[官方任务说明](https://docs.volcengine.com/docs/ark/list-video-generation-tasks-api?lang=zh)指出，部分 2.5 任务要到消费阶段才返回参数错误。任务 ID 只证明创建成功，不证明所有参数均已通过模型校验。

遇到 `InvalidParameter.TaskTypeConstraint` 时，核对最终发送的 `ratio`、`duration` 和每个素材的 `role`，包括省略字段。`fail_to_fetch_task` 等外层包装不能覆盖内部的具体参数原因。任务列表、画布及重启后的记录应保留同样的调整建议和排查编号。

若发送体没有比例却收到比例错误，应继续核对中转的默认值和转换结果；不能仅凭这条报错判定客户端、网关或供应商中的某一方承担全部原因。失败任务不自动原样重提。

显式选择全能参考时，Seedance 2.5 请求传入
`omni_reference_task_type=reference`；视频编辑和延长分别传入 `edit` / `extend`。
企业 Videos 请求使用 metadata，原生和兼容插件使用对应顶层字段；2.0 与未指定模式保留原行为。
供应商 `model_temporarily_unavailable` 归类为模型暂不可用，不能解释成用户余额不足。

## 参考视频像素与元数据校验

视频时长已知不等于尺寸已知。前端会为本地视频和受管资源补读宽高；后端对本地资源及内嵌 MP4/MOV 读取真实容器尺寸，覆盖旧元数据。尺寸仍无法读取时停止提交，提示重新导入；`asset://` 是供应商持有的素材，保留标识交由供应商校验。

像素限制针对每个参考视频的宽×高，与输出分辨率、文件体积、参考图片规则相互独立。错误提示应保留素材序号、实际尺寸、总像素及允许范围，并在任务历史再次读取时保留调整方法。不会自动放大、裁剪或重试用户素材。

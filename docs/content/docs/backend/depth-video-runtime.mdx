# 本地深度视频组件

视频节点的“深度动作捕捉”在本机生成近白远黑的灰度参考视频。使用固定的 Video Depth Anything Small 模型，输入最多 15 秒，输出为 1920×1080，普通帧率保持不变，超过 30 fps 时转换为 30 fps。

首次使用会下载独立运行组件和模型；无需自己安装 Python。CPU 处理可能较慢且占用较多内存，请留出足够磁盘空间。Windows CPU 运行包压缩后约 0.8 GiB、展开约 3.6 GiB，下载缓存和安装文件都会保留；CUDA 包更大，安装时还需要临时解压和分片拼接空间。

组件下载与桌面更新共用代理选择规则：显式环境代理优先，否则读取 Windows/macOS 当前用户的静态系统代理，并保留排除地址规则。修改系统代理后重试会读取新配置，不需要在 BeefTV 里重复填写代理。

## 平台与 CUDA 社区测试

- Apple Silicon Mac 保持现有 MPS 路径。
- Windows x64 没有可用 NVIDIA GPU 时使用 CPU。
- 检测到 NVIDIA GPU 后，先运行真实 Small 模型探针，通过后才使用 CUDA。CUDA 设备错误最多回退 CPU 一次；素材、下载、哈希或取消错误不会触发换设备重试。
- CUDA 包已通过构建与搬迁检查，但真实 NVIDIA 推理仍属社区测试。反馈时请提供显卡型号、驱动版本、BeefTV 版本、输入视频尺寸/时长和任务错误详情，勿附带密钥。

Windows CPU 在一台 AMD 显卡机器上完成了 2 秒和 15 秒合成视频验证，帧数分别为 60 和 450，输出全片可解码。该测试不能代表所有机器的性能或真实人物素材效果。

## 发布与回退

`release-depth-runtime.yml` 在官方 main 上构建 CPU 和 CUDA 包，经搬迁自检、CPU 真模型探针、逐文件/分片及完整包哈希检查后，发布不可覆盖的 `depth-runtime-v2` 组件 Release。CUDA 大包分为小于 2 GiB 的资产。

签名复用仓库现有 Ed25519 发布密钥，私钥仅在 GitHub Actions 签名步骤使用。Windows 应用通过编译参数嵌入公钥，先验签清单，再校验下载文件。Mac 的旧清单保持不变。桌面发布工作流会先验证已上线的组件清单；组件发布失败时，不会发布宣称支持该功能的桌面更新。

同一应用进程内的组件安装串行执行，避免不同任务共写缓存；推理不会被安装锁串行化。取消可中断安装等待、解压、文件校验及 Python/FFmpeg 进程树。

组件资产不覆盖。修复组件时使用新组件标签及新的受信清单地址，并发布引用该地址的新应用版本。桌面回退遵循自动更新发布文档，以更高版本号发布已知可用代码；不降低或覆盖已公开的版本。

# 本地后端代码地图

BeefTV 是单用户、本地优先的桌面应用。项目、画布、素材和任务落到本地 SQLite 与工作区目录；模型生成仍可通过 Provider/Protocol 适配器访问外部 API。旧内置 Agent 已从产品运行面退场，其历史运行/偏好/记忆数据仍保留在本地数据库。

## 运行链路

模型服务设置由 `web/src/pages/settings/model-service-editor.tsx` 管理添加和编辑草稿；`model-service-presets.ts` 依据已启用的协议插件填写初始配置。`model-connection-test.ts` 通过正常后端生成任务验证结果。`internal/workspace/provider_config.go` 持有配置版本、保存冲突和文件读写，`internal/localcrypto` 统一工作区凭据加解密格式。

RunningHub 设置由 `web/src/pages/settings/runninghub-settings-pane.tsx` 管理，与普通模型渠道分开。参数读取经过 `handler/runninghub.go` 的本地身份和插件校验，再进入 `app/runninghub_management.go` 与 `provider/workflow`；画布选择由 `generation-workflow-execution.ts` 解析，生成沿用持久任务入口。参考素材经 `generation/media.go` 的归属校验与字节读取，再由 `provider/workflow/client.go` 用工作流 Key 上传并映射 `fileName`。本机 ComfyUI 服务尚未接通。

正式视频节点在 `ModelPicker` 的附加分组中选择 RunningHub 条目，`canvas-workflow-controls.tsx` 将映射后的分辨率、比例、时长放进原有底栏，其余字段与素材检查放进参数弹层。`workflow-video-controls.ts` 提供供应商无关的字段识别、具体字段映射、摘要和默认值规则；设置页的 `workflow-video-controls-editor.tsx` 保存每个条目的映射与显示开关。`canvas-workflow-inputs.ts` 核对素材槽位和参数。工作流产物由 `provider/workflow` 保留为完整 `outputs` 数组，`taskdelivery` 逐项写入资源与媒体素材，`taskbinding` 核验资源并回填主输出及结果集合。前端 `generation-outputs.ts` 与 `canvas-generation-outputs.ts` 定义供应商无关的结果引用、主输出选择与展开规则，`canvas-generation-results.tsx` 提供预览和添加到画布操作。

`canvas-connection-policy.ts` 根据目标节点的工作流渠道跳过普通模型容量检查，保留节点输入类型检查。`canvas-node-generation.ts` 在生成上下文中保留工作流的图片与角色卡混排槽位，解析时每张角色卡只物化一张主参考图，再按原槽位顺序组装任务输入；普通模型仍按容量追加角色多视图。角色卡没有参考图时明确拒绝提交，不压缩后续槽位。

工作流生成上下文自动合并连接的文字，去除已显式引用的重复追加。`task/admission.go` 按模型目录解析后的有效配置判断是否允许空提示词，`generation/executor.go` 在配置解析和工作流分流后保留普通模型的非空校验。`provider/workflow/mapping.go` 对空提示词省略覆盖，即使字段标为必填也由上游判断，不伪造提示词或覆盖默认值；其他字段校验保持有效。

`generation-output-media.ts` 通过共享鉴权客户端读取输出字节，并按运行环境选择浏览器 Blob 下载或 Wails 的 owner 资源保存接口；音频预览在结果面板管理取消、账号切换和 Blob URL 释放。展开输出复用 `canvas-generation-layout.ts` 的空位计算，避免分次添加时覆盖已有节点。

`services/canvas-generation-outputs.ts` 在添加媒体或选择主输出前查询任务交付记录，按输出索引核对资源并取得对应素材 ID；`canvas-generation-outputs.ts` 同时写入素材与资源引用，随后沿用普通画布保存流程。`app/workflow_adapter.go` 将上游排队、运行和下载状态交给租约约束的生成阶段端口，不修改任务进度或终态；`provider/workflow/client.go` 在读取产物前记录下载阶段。

设置页私有的 `runninghub-metadata-request.ts` 在请求存续期间订阅站点、Key 和账号变化，立即取消旧请求并在写回前复核身份；订阅在取消或完成后释放。`provider/workflow/protocol.go` 按固定顺序识别规范化的输出字段。`task.CanonicalOutputs` 保留主线的 `taskType` 参数，深度捕获任务使用独立结果结构，工作流任务使用多输出数组；交付、恢复和绑定继续共用现有任务机制。

```text
Wails / local dev
  -> internal/bootstrap        组合根、数据库、HTTP 生命周期
  -> internal/localapp        本地能力端口
  -> internal/{task,asset,project,workspace}
  -> internal/app             跨域编排与尚未拆分的核心实现
  -> internal/{generation,provider,protocol,outbound}
  -> external model APIs
```

## 主要目录

| 边界 | 位置 | 职责 |
| --- | --- | --- |
| 组合根 | `backend/internal/bootstrap` | 打开本地数据、组合窄服务、启停 HTTP 与 worker |
| 本地应用 | `backend/internal/localapp` | 定义 workspace/project/asset/task/generation/provider-config 端口（旧 Agent 空端口已移除） |
| 工作区 | `backend/internal/workspace` | 本地身份、模型配置快照；ZIP 导入导出不在此包 |
| 任务域 | `backend/internal/task` | 本地任务命令、列表读模型、生命周期，以及本机 ffmpeg/转写/深度捕捉的准入 |
| 生成结果交付 | `backend/internal/taskdelivery` | 第一段把生成 dataURL/字节写入本地资源并改写 ResultJSON；第二段在任务成功后物化素材。不发起新的上游生成。远端产物经 `outbound.DownloadResumable` 断点续传下载：无总超时，只有头部与空闲超时，半成品在 `<data>/cache/artifact-downloads` 下按身份复用 |
| 生成域 | `backend/internal/generation` | 统一生成输入、引用、能力、registry 协议调度和失败归类 |
| 供应商适配 | `backend/internal/provider`, `protocol`, `outbound` | 外部模型 API、自定义渠道和插件协议 |
| 模型目录 | `backend/internal/modelcatalog` | 能力合同、渠道目录校验/解析/合并与 BeefAPI/WhatsToken overlay；出站 HTTP 仍走 outbound |
| 协议插件 | `backend/internal/plugins` | registry、安装/启用和渠道设置用的 provider 能力目录；live 快照按 Runtime 隔离 |
| Seedance 参考素材预上传 | `backend/internal/app/beefapi_seedance_preupload.go` | 仅内置 BeefAPI Seedance：本机后端把参考图片/视频/音频换成短期 HTTPS 链接后再提交 `/v1/videos`；本机文件在上传完成前保持本地引用 |
| 数据 | `backend/internal/database`, `repository` | SQLite schema、迁移和持久化 |
| 剪辑语义计划 | `backend/internal/editing` | 版本化时间线渲染计划：选择、顺序、空隙、裁剪、音量、字幕与输出宽高/帧率/采样率。不依赖 `internal/app`，不接受本地路径或 ffmpeg 参数 |
| 视频预览与工具 | `backend/internal/playback`、`backend/internal/mediatools` | 按需 H.264 预览、单任务转码、用户预览缓存清理；播放和剪辑共用随包 FFmpeg 解析，显式路径优先于随包工具，最后查 PATH |
| HTTP | `backend/internal/handler` | 本地 `/api` 合同、输入限制和响应封装 |
| 企业连接 | `backend/internal/beefapi` | 设备授权、本机密钥和连接状态 |
| 本机 MCP | `backend/cmd/beeftv` | `beeftv mcp serve` 使用官方 MCP SDK，经 `/api/ops` 访问本机工作区 |
| 桌面更新发布 | `backend/cmd/update-release` | 生成更新密钥、打包 zip、签署 `desktop-update.json` |
| 前端 | `web/src` | React 画布、项目、素材、模型配置与插件 UI |

## 硬边界

- 不提供登录、注册、计费、支付、公开分享或云存储路由。
- 内置 BeefAPI 密钥保存在本机加密连接存储中；其他手动渠道密钥仍在本地模型配置中。密钥不进入画布快照或日志响应。
- 外部 API 是生成能力，不是 SaaS 数据面；不得在“本地化清理”中删除 Provider、Protocol、自定义渠道或插件扩展点。
- worker 并发策略由任务运行时管理，架构整理不得顺带改变其行为。

HTTP 稳定合同见 [HTTP API](/docs/backend/http-api) 和 `backend/internal/handler/openapi.yaml`。

## 使用入口

此 fork 默认启用 aihubkit 适配。打开应用先登录，成功后进入原有工作台。登录页提供注册及邮箱验证码；侧栏底部的「aihubkit 账号」入口提供额度刷新、兑换码充值、分组模型导入和使用日志。账号注册、分组权限与充值规则由 aihubkit 服务决定。

初次登录会读取默认分组模型，按明确的接口类型选择协议。没有已知接口类型的模型可在账号面板选择已安装的协议后导入。导入保留其他渠道和已选默认模型；模型目录可见不代表已通过实际生成验证。官方 Provider、Protocol、自定义渠道和插件继续使用原有流程。

账号面板「分组与模型」中的“导入所选模型”会创建绑定所选分组托管凭据的 aihubkit 渠道；这就是账号分组与模型调用的关联步骤，不再提供重复的绑定入口。通过原有「模型配置」手工创建且已有 API Key 的渠道保持独立，不会被登录流程改写凭据。

## 启停与上游同步

桌面和 server 启动入口通过 `internal/integrations.Open` 选择宿主：`BEEFTV_INTEGRATION=aihubkit`（默认）启用平台登录，`BEEFTV_INTEGRATION=local` 直接使用官方本地运行时。变更后需重启后端。Compose 部署可通过额外的 Compose 覆盖文件给 backend 设置该环境变量。前端从宿主读取会话状态，只有明确的集成接口 404 才使用官方本地模式；认证或网络错误不会降级绕过登录。

平台后端集中在 `backend/internal/integrations/aihubkit/`，前端集中在 `web/src/integrations/aihubkit/`。官方组合根仅增加 `HostRuntime` 和服务配置 hook；凭据与参考存储通过 `app.Extensions` 的可选端口接入。生成域只选择参考存储实现及检查整批参考链接的有效性，不依赖平台账号实现。视频请求复用现有 `aihubkit-video` 协议插件，不另建生成队列或画布流程。

合并官方更新时重点检查：desktop/server 组合入口、`app.Extensions` 凭据解析、生成执行/预检的参考存储选择、前端启动壳及账号菜单插槽。保留官方最新核心逻辑，再调整这些接入点。每次新需求遵守根 `AGENTS.md` 的「Fork 与上游同步原则」。

## 账号与凭据边界

账号宿主仍是单操作者本地工作台，同一后端同时只打开一个账号，不是共享多租户服务。数据目录按平台源和用户 ID 的哈希分隔，路径为 `<data>/aihubkit/accounts/<scope>/`；每个账号拥有独立 SQLite、资源树、模型快照与本地加密密钥。浏览器缓存按相同账号 scope 隔离。不会自动导入原本地工作区的数据。

登录密码仅用于登录请求。远端登录 Cookie 在后端临时 Cookie jar 内换取管理凭据；管理凭据留在内存。每个模型分组的推理 Key 使用工作区 `localcrypto` 加密保存在 `aihubkit-keys.enc`，前端只保存 `aihubkit:<group>` 引用。托管凭据仅解析到绑定的平台 origin，不能通过自定义 URL 发往其他主机。

应用会话凭据放在内存及 HttpOnly Cookie 中，写请求必须携带当前会话 header；退出后旧会话失效。退出先保存浏览器状态、暂停前端生成消费者，再关闭本机工作区并重新加载页面。上游已接受的任务仍可能执行和计费，退出不等于取消上游任务；再次登录同一账号后由官方任务恢复流程处理已记录任务。

公网部署需使用 HTTPS、明确配置 `CANVAS_CORS_ORIGINS` 并保护数据目录。平台宿主仅支持本地 SQLite；不接受另设远程数据库 URL。重启宿主或迁移数据目录后需重新登录。

## 通用文件上传

临时文件接口是通用存储，适配不按图片限制 MIME，支持图片、视频、音频及其他文件类型。工作台当前在生成参考素材链路使用它；本地导入和保存素材仍由官方资源系统管理。

当服务地址严格属于 `https://apimodel.aihubkit.com`，且模型协议要求公网参考 URL 时，任务实际执行阶段才会读取当前账号拥有的本地资源，通过管理凭据申请 `POST /v1/temporary-files`，再将原始字节 PUT 到返回的 `upload_url`，使用返回的 `url` 提交模型。临时上传既适用于账号面板导入的托管渠道，也适用于原有模型设置中手工配置的 aihubkit 渠道，不要求用户配置 S3。其他源站仍使用其原有参考存储配置。

预检与排队不上传，也不将临时签名 URL 写入排队输入。PUT 客户端不携带平台 Authorization 或 Cookie，只允许票据中的存储请求头；上传与读取地址均需通过公网 HTTPS 校验。有效期以接口返回的 `expires_in` 为准，上传完成后再次检查整批链接，避免先上传的文件已过期仍提交生成。链接有效期不足会在生成前报错，需要重新提交。

文件大小、配额、保留周期与上游抓取时机由线上服务决定，适配不硬编码图片类型或固定大小上限。临时 URL 不应当作永久素材地址。

## 本地接口

全部位于 `/api/integrations/aihubkit/`，使用工作台标准 `{ code, data, msg, reason }` 信封。除 `session` 查询及登录/注册/验证码外，均要求已登录。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `session` | 集成启用与当前会话状态 |
| POST | `login` / `register` / `verification` | 登录、注册、发送验证码 |
| GET | `self` / `logs` | 当前账号额度、脱敏使用日志 |
| POST | `catalog` | 读取授权分组模型目录 |
| POST | `topup` | 兑换码充值 |
| POST | `logout` | 关闭账号工作区并使会话失效 |

外部协议见 [账号系统接口](https://86bdknokqu.apifox.cn/9446929m0) 和 [临时文件接口](https://86bdknokqu.apifox.cn/9496843m0)。

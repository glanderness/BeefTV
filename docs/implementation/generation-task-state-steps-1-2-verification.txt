子场景全部通过：

2. 原渠道不变：一次原请求发送，URL、Authorization、Idempotency-Key、正文与原快照完全一致。
3. 当前任务改选其他渠道：仍使用原渠道，运行时统计与并发渠道也不改到新渠道。

5. 原渠道停用、删除、原 token 替换、原源地址替换、快照渠道或 token 不一致：均零发送；发送次数不增加。
6. 发送前检查通过、准入前再停用或换 token：仍零发送，未借其他启用渠道重发。
7. 对这些不能恢复的失败任务再走真实恢复编排：持久化 unrecoverable，读投影 failed + confirm；原任务、routeRun、attempt 数不增加。
8. 渠道表读取失败：不发送，不写永久恢复结论，仅退避。
9. 原 worker 对已发送 running 图片继续/重启重放时，停用、删除、换 token 也零发送；不是仅新增扫描器有保护。
10. 假上游对原凭据返回 401/403：只尝试原身份一次，停止自动取回，不切换凭据，结论不代表未计费。
11. 本地配置中的 beefapi/custom 直连：原身份可用；轮换、停用、删除均不可用。

新快照的 ChannelID 保存在既有加密 JSON 内，不新增数据库身份表；原 Header 的实际鉴权值不更新为当前 token。测试使用假凭据，不向真实 BeefAPI 发 POST。

## 一、必须修复

### P1：普通思考文本未经凭据过滤，合成宿主 token 与 API Key 原样进入网络和历史

位置：`agent-host/durable-turn-projection.mjs:21–29`；流式出口同文件 `:110–111`，历史写入调用点 `agent-host/durable-session-owner.mjs:1116`。

`readableThinking()` 只检查块类型、`redacted` 和非空文本，直接返回 `block.thinking`。流式路径和 `durableReasoningSegments()` 都没有清理已知宿主／模型凭据或明确的凭据格式。丢弃 `thinkingSignature` 等结构化字段，不能保护普通文本里出现的凭据。

**独立实测：** 在真实宿主的本地 Anthropic SSE 替身中，第二段思考包含合成的 `host_token="synthetic-lifecycle-host" api_key="sk-review-only-123456"`。前者与该测试宿主实际使用的合成认证 token 相同。`/chat` 的 NDJSON 原样包含该 token，`/history` 原样包含该合成 API Key。假签名仍被正确剔除。这里证明的是合成数据的外传路径，没有使用或声称泄露真实凭据。

这不满足输入方案 §4.2 对新思考出口的凭据清理要求。默认折叠、纯文本渲染都不能阻止响应已经包含凭据。

最小修复：在实时、终态与历史共用的公开投影中清理已知凭据和明确凭据格式；已知秘密的未完整前缀应暂缓输出，不能等后续分片到齐才替换。不能依赖评估脚本的 `redactSecrets()`，该函数并未接入生产展示路径。补充完整值与跨分片的负向断言，同时保持官方存储与协议回放数据原样。无需声称能识别任意自然语言中的所有秘密。

### P2：终态只投影最终答案消息，工具调用前的思考会消失

位置：`agent-host/durable-session-owner.mjs:1116`，取数来源为 `:1097–1098`；前端采用终态的调用点为 `web/src/pages/canvas/use-canvas-assistant.ts:506`。

实时 `compose()` 会收集本轮所有已提交助手消息，以及正在生成的消息。`completionRecord()` 却只从 `settled.answer` 指向的单条助手消息调用 `durableReasoningSegments(assistant)`，不是本轮完整思考。

**独立实测：** 使用同一个真实宿主和官方 Pi 1.3.0 运行时，本地替身顺序返回「第一段思考 → `canvas_get` 工具调用 → 第二段思考 → 正文」。恰好发出两次本地模型请求；最后一条 `reasoning_snapshot` 有两段，`turn_end.reasoning` 和历史都只有第二段。

如果最终消息有思考，前端直接用这个非空终态数组替换实时数组，第一段在结束时消失；如果最终消息没有思考，前端虽然暂用流式数组，但历史没有同一份数据，重新读取后仍会丢失。`send()` 的 `finally` 还会主动重新读取历史，不能把内存回退当成持久修复。

最小修复：用原提交、补充输入和确切结束条目限定本轮范围，在终态与历史中复用同一份完整投影；片段身份包含 entry 与内容下标。不能扫描会话最后一条消息，也不能仅靠前端保留旧数组。补真实宿主的跨工具成功、停止及最终消息无思考用例，分别比较流式、终态和重新读取历史的内容。

[固定源码：终态投影](https://github.com/glanderness/BeefTV/blob/7880e2031c5e86881b49dd5f65fcb40b538f9901/agent-host/durable-session-owner.mjs#L1116)

### P2：思考被替换为空或 redacted 后，前端收不到清空通知

位置：`agent-host/durable-turn-projection.mjs:109–111`；终态回退同样受影响：`web/src/pages/canvas/use-canvas-assistant.ts:506`。

`reasoning_snapshot` 定义为完整数组替换，但发出事件的条件额外要求 `next.reasoning.length` 非零。一旦官方 block/message 替换或 snapshot 把唯一可读块移除，宿主内部会清空 `reasoning`，网络却不发送 `segments: []`。前端只有收到 `onReasoning` 才替换数组，因此仍显示旧思考和旧阶段。

**独立事件夹具：** 先发送可读 `thinking_start`，随后用官方支持的 `block` 更新替换同一位置，分别替换为空 thinking 和 `redacted: true` thinking。两次结果均为「宿主 0 段、清空事件 0 条、客户端仍 1 段」。该复现证明替换事件处理错误，不据此断言真实供应商一定会把已读文本改成 redacted。

如果此时终态没有 reasoning，前端的 `end.reasoning?.length ? … : current.reasoning` 还会把应移除的旧内容当作有效终态保留下来。应区分“从未提供思考字段”和“明确替换为空数组”。

最小修复：已有非空投影变为空时发送完整空数组；初始无思考时仍可不发空事件。终态和历史也应表达权威空值，前端只在字段确实缺失时才考虑回退。补从非空到空、redacted、整条消息替换和 snapshot 替换的负向用例。

空值替换可用下面的无模型片段复核；同样可把 replacement 换成 `{ type: 'thinking', thinking: '' }`：

```js
import { createDurableTurnProjection } from './agent-host/durable-turn-projection.mjs';
const projection = createDurableTurnProjection();
let shown = [];
function accept(event) {
  const payloads = projection.accept(event);
  for (const payload of payloads) {
    if (payload.type === 'reasoning_snapshot') shown = payload.segments;
  }
  return payloads;
}
accept({ type: 'snapshot', afterEntry: 0, entries: [] });
accept({ type: 'message_start', message: { role: 'assistant', content: [] } });
accept({ type: 'message_update', changes: [{ type: 'thinking_start', contentIndex: 0,
  block: { type: 'thinking', thinking: '将被替换的旧内容' } }] });
const payloads = accept({ type: 'message_update', changes: [{ type: 'block', contentIndex: 0,
  block: { type: 'thinking', thinking: '不透明占位', redacted: true } }] });
console.log({ host: projection.reasoning.length, events: payloads.length, shown: shown.length });
// 当前 head：{ host: 0, events: 0, shown: 1 }
```
